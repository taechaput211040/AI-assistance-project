# Prompt Log — Player Feedback Insight Report

เอกสารนี้รวบรวม **prompt ที่ใช้จริง** ในการให้ AI (Claude) จัดหมวดหมู่และสรุป feedback 300 รายการ พร้อมคำอธิบายเหตุผลของแต่ละ prompt และวิธีนำผลไปใช้

---

## Prompt 1 — Classification (จัด Sentiment / Category / Priority / Owner)

> **System / Instruction**
>
> คุณเป็นนักวิเคราะห์ player feedback ของเกมมือถือแนว gacha RPG
> ฉันจะส่ง feedback ภาษาไทยมาให้ทีละชุด (มี `feedback_id` + ข้อความ)
> ให้จัดป้ายกำกับแต่ละรายการเป็น JSON โดยใช้ schema นี้เท่านั้น:
>
> ```json
> {"id": "...", "category": "...", "sentiment": "...", "priority": "...", "owner": "...", "theme": "..."}
> ```
>
> **กติกา**
> - `category` เลือกได้ค่าเดียวจาก 9 หมวดนี้ (อิงตาม Category_Guide ของชุดข้อมูล):
>   Bug / Technical Issue, Reward / Economy, Gameplay / Balance, Event Feedback,
>   Gacha / Monetization, UX / UI, Content Request, Positive Feedback, Account / Payment
> - `sentiment` = Positive | Neutral | Negative
>   ตัดสินจาก "แก่นความหมาย" ไม่ใช่คำลงท้ายสุภาพ เช่น "...ไม่แฟร์ ขอบคุณครับ/ค่ะ" = Negative
>   ข้อความที่ทั้งชมและติ (เช่น "ธีมน่ารักแต่ภารกิจซ้ำ") = Neutral
> - `priority` = P1 | P2 | P3
>   - P1 = บล็อกการเล่น / กระทบเงินหรือบัญชี (crash, เด้งออก, ของไม่เข้า, ล็อกอินไม่ได้, แลคจนเล่นบอสไม่ได้, support ค้าง)
>   - P2 = กระทบประสบการณ์หลักแต่ยังเล่นได้ (บาลานซ์, เศรษฐกิจในเกม, กาชา, grind, onboarding)
>   - P3 = ปรับปรุงเล็กน้อย / คำขอฟีเจอร์ / ความเห็นทั่วไป
> - `owner` = ทีมที่รับผิดชอบแก้ เลือกจาก:
>   Engineering, Game Design, Economy, Monetization, LiveOps, Product/UX, Player Support, Community
> - `theme` = วลีสั้น ๆ สรุปแก่นของปัญหา (ใช้จัดกลุ่มซ้ำได้)
>
> ตอบเป็น JSON array เท่านั้น ห้ามมีคำอธิบายอื่น

**ทำไม prompt นี้:**
- **บังคับ schema + enum** เพื่อให้ผลออกมาเป็นโครงสร้างเดียวกันทุกแถว ป้อนเข้า dashboard/sheet ได้ทันที ไม่ต้องมา clean ทีหลัง
- **ระบุเกณฑ์ P1/P2/P3 อย่างเป็นรูปธรรม** กัน priority เลื่อนลอย — ผูกกับ "ผลกระทบต่อการเล่น/รายได้" ซึ่งเป็นภาษาที่ทีม product เข้าใจ
- **สั่งให้ดู 'แก่นความหมาย' ไม่ใช่คำลงท้าย** เพราะชุดข้อมูลนี้เติมคำสุภาพ/คำบ่นแบบสุ่มต่อท้าย (เช่น "ขอบคุณครับ/ค่ะ", "เพราะกระทบการเล่นพอสมควร") ซึ่งจะหลอก sentiment ถ้าใช้คีย์เวิร์ดตรง ๆ
- **เพิ่มฟิลด์ `owner`** ตาม rubric เพื่อให้ report ไม่ได้แค่บอก "มีปัญหาอะไร" แต่บอกได้ว่า "ใครต้องแก้"

## Prompt 2 — Summarization (สรุป Insight ระดับผู้บริหาร)

> จากผลการจัดหมวด feedback ทั้ง 300 รายการ (แนบตารางนับจำนวนตาม category / sentiment / priority / owner / theme)
> ช่วยสรุปให้ผู้บริหารอ่านใน 1 นาที โดยมีหัวข้อ:
> 1. **ภาพรวม** — สัดส่วน sentiment, จำนวน P1
> 2. **Top Issues** — 5–8 ปัญหาที่ impact สูงสุด (impact = ปริมาณ × ความรุนแรง × ความลบ) พร้อมทีมเจ้าของ
> 3. **Patterns** — รูปแบบ/ธีมที่เกิดซ้ำข้าม segment, platform, version
> 4. **Risk** — ความเสี่ยงเชิงธุรกิจ (churn, รายได้, ชื่อเสียง) ถ้าไม่แก้
> 5. **Recommended Action** — สิ่งที่ควรทำต่อ แยกเป็น "แก้ทันที (P1)" และ "วางแผน (P2/P3)"
> เขียนกระชับ ใช้ตัวเลขประกอบ และให้ actionable

**ทำไม prompt นี้:**
- **ให้ AI สรุปจากตัวเลขที่ aggregate แล้ว** (ไม่ใช่ข้อความดิบ 300 แถว) เพื่อลด hallucination และให้สรุปอิงข้อมูลจริง
- **กำหนดสูตร impact ชัดเจน** เพื่อให้การจัดอันดับ "ปัญหาสำคัญ" สม่ำเสมอและอธิบายได้ ไม่ใช่ความรู้สึก
- **บังคับให้แยก Risk และ Action** ตาม rubric — report ที่ดีต้องตอบ "แล้วไง / ต้องทำอะไรต่อ" ไม่ใช่แค่ตัวเลข

## หมายเหตุการนำไปใช้จริง (Implementation note)

ชุดข้อมูลนี้สร้างจาก **template** — 300 รายการเกิดจากแก่นข้อความ ~65 แบบ ที่ถูกเติม prefix/suffix แบบสุ่ม
ในทางปฏิบัติจึงทำงาน 2 ขั้นเพื่อความถูกต้องและประหยัด token:

1. ให้ AI (Claude) อ่านและ **จัดป้ายตาม Prompt 1 ที่ระดับ "แก่นความหมาย" (65 คลัสเตอร์)**
2. **apply ป้ายเดียวกันลงทุกแถวที่มีแก่นเดียวกัน** อย่างสม่ำเสมอ (ดู `scripts/enrich.py`)

ข้อดี: รายการที่ความหมายเหมือนกันได้ป้ายตรงกัน 100% (consistency) — ดีกว่าการยิง LLM ทีละแถวที่อาจให้ผลต่างกันในข้อความที่เหมือนกัน
ข้อจำกัด: ถ้าเป็นข้อมูลจริง (free-text หลากหลาย ไม่เป็น template) ต้องยิง Prompt 1 แบบ batch ทีละ ~20–50 แถวเข้า LLM API จริง — โครงสร้าง prompt เดียวกันใช้ได้ทันที
